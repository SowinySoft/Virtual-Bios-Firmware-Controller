VBFC: A Programmable SPI Interposer for BIOS Feature Unlocking and Firmware Security

Abstract — The BIOS firmware is the most privileged software layer in any x86 system, yet consumers and security researchers have limited means to inspect, modify, or extend it without expensive hardware programmers. We present the Virtual BIOS Firmware Controller (VBFC): an open-source, low-cost SPI interposer that sits between a motherboard's chipset and its SPI flash chip, selectively substituting bytes in real-time. Built around the Raspberry Pi RP2040 microcontroller and a 16 MB extension flash (W25Q128), the VBFC implements a cryptographic signing layer that prevents unauthorized image injection, an address translation map for transparent region remapping, an in-flight byte patching engine, and a SPI bus transaction sniffer. This paper covers the architecture, hardware design, firmware implementation, host software toolchain, and deployment considerations.

1. Introduction

Modern x86 platforms rely on SPI (Serial Peripheral Interface) flash to store boot firmware, Intel Management Engine (ME) / AMD Platform Security Processor (PSP) firmware, and UEFI variables. The chipset acts as SPI master and reads/writes this flash during boot and runtime. The VBFC takes a novel approach: instead of replacing or reflashing the chip, it interposes on the SPI bus and selectively shadows regions from a separate extension flash. This allows the interposer to present a modified view of BIOS contents without ever modifying the original chip.

2. System Architecture

2.1 Hardware Design

Components: RP2040 (264 KB SRAM, 2 MB flash), W25Q128 (16 MB extension flash), 74LVC1G3157 analog mux, SOIC-8 interposer board.

Signal flow: The PCH's CS/SCK/MOSI/MISO signals route through the interposer. MISO is multiplexed between the original flash (pass-through) and the RP2040 (active shadow). A bypass jumper (GPIO 18) forces hardware pass-through regardless of firmware state.

2.2 Firmware Architecture

The firmware runs a round-robin poll loop handling three concurrent tasks:

  • SPI bit-bang slave — decodes PCH transactions by monitoring SCK edges via a state machine: IDLE → CMD → ADDR (3 bytes) → DUMMY → DATA
  • USB CDC service — text-command and base64 binary protocol over USB virtual serial port
  • Watchdog safety — 500 ms watchdog, bypass jumper monitoring, fault-driven pass-through

SPI Arbiter Flow

enter_data_phase() → shadow_map_lookup()
  → ORIG? → release MISO, chip answers directly
  → EXT?  → drive MISO, load_tx_byte()
    → map address through ext_offset
    → 256-byte prefetch cache (W25Q128 SPI1)
    → patch_table_match() for byte substitution
    → miso_drive_bit() — bit-bang MISO per SCK falling edge

2.5 UF2 Firmware Format

The RP2040 firmware is distributed as a UF2 file [11], a 512-byte-block container format designed by Microsoft. Each block: 32-byte header (magic0=0x0A324655, magic1=0x9E5D5157) + 256-byte payload + 220-byte pad + 4-byte trailer (0x0AB16F30). A Python converter (vbfc_uf2.py) generates UF2 without picotool.

4. Security Analysis

Threat model: Attacker can write arbitrary data to ext-flash via USB. Firmware and compiled-in HMAC key are trusted.

  • HMAC-SHA256 authentication: All served EXT images must pass HMAC verification before data reaches the PCH
  • Anti-rollback: Monotonic version counter, older signed images rejected
  • Bypass jumper: Hardware pass-through regardless of firmware state
  • Fault handler: CRC failures, invalid map, watchdog timeout → automatic pass-through

5. Use Cases

  • BIOS Backup/Restore: Full chip dump via FLASH BACKUP, restore via ULOAD
  • Hidden-Feature Unlocking: analyze command scans for UEFI variables, ROMSIP tables, disabled PCI devices → emits PATCH ADD commands
  • Dual-BIOS: Bank 0 (0x2000) / Bank 1 (0x802000), switchable via bank command
  • Defective-Block Detection: check command CRC32s blocks and diffs against known-good reference
